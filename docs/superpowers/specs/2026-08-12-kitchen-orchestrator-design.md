# Кухонный оркестратор — дизайн

## Что это

Одностраничная PWA: вводишь позиции (что готовить и сколько минут каждая занимает) и время подачи — приложение считает назад, когда что ставить, показывает живой таймлайн и пищит, когда наступает старт очередного этапа. Работает офлайн, ставится на телефон с домашнего экрана.

Задача, которую все решают в голове и все путаются: «гуся 3 часа, картошку 40 минут, соус 15 — когда что ставить, чтобы всё поспело к восьми?»

## Критерии успеха (от совета)

- Встроенный повторяющийся триггер возврата: каждая готовка «к времени» — повод открыть.
- Ноль персональных данных, ноль сервера: статика на GitHub Pages, состояние в localStorage.
- Переживает охлаждение автора: без зависимостей и сборки нечему протухать.
- Ниша свободна: мультитаймеры считают вперёд и параллельно; обратный расчёт от подачи не делает никто (проверено поиском 2026-08-12).

## Подходы (рассмотрены)

1. **Vanilla JS, статика без сборки — выбран.** Ноль зависимостей, деплой = git push, логика расчёта — чистый ES-модуль, тестируемый `node --test`. Соответствует всем критериям совета.
2. React + Vite PWA — быстрее итерации по UI, но сборка и зависимости протухают, против критерия «переживает охлаждение».
3. Нативное приложение — мимо: карточка идеи прямо говорит PWA/офлайн, и дистрибуции без Apple Developer Program у автора нет (урок mac-01).

## UX-поток

Один экран, три зоны сверху вниз:

1. **Время подачи** — `<input type="time">`. Если введённое время сегодня уже прошло — считаем, что это завтра (подпись «завтра» рядом с полем).
2. **Позиции** — список строк «название + минуты», кнопка «Добавить». Многоэтапные блюда пользователь вводит отдельными строками сам («утка — духовка, 180», «утка — отдых, 20»): никакой модели этапов в MVP.
3. **Таймлайн** — появляется при валидном вводе (≥1 позиция, время задано). Позиции отсортированы по времени старта. Каждая строка: время старта, название, статус:
   - `ждёт` — до старта («старт в 17:40 · через 25 мин»);
   - `пора ставить` — момент старта наступил: тройной бип, строка подсвечена акцентом первые 60 секунд;
   - `в работе` — от старта до подачи;
   - `подано` — после времени подачи (финальный бип в момент подачи).

Сверху таймлайна — крупный обратный отсчёт до подачи. Кнопка «Сброс» очищает план.

Если старт какой-то позиции уже в прошлом («не успеваем») — строка помечается «старт был N мин назад — ставь сейчас», без пересчёта времени подачи: решение сдвинуть подачу принимает человек.

## Расчётная модель

Чистый модуль `schedule.js`, ни одной ссылки на DOM:

```
computeSchedule(items, serveAt, now) -> { serveAt, entries: [{ id, name, minutes, start, status }] }
```

- `items`: `[{ id, name, minutes }]`, `serveAt`/`now`: `Date`.
- `start = serveAt − minutes`.
- `status`: `waiting` (now < start), `due` (start ≤ now < start+60с), `cooking` (start+60с ≤ now < serveAt), `served` (now ≥ serveAt). `due` — отдельный статус, чтобы UI знал, когда подсвечивать и бипать.
- Сортировка entries по `start` возрастанию; при равенстве — по порядку ввода.
- `resolveServeDate(hhmm, now) -> Date` — сегодня или завтра, если время уже прошло.
- Функции детерминированы: `now` всегда передаётся параметром.

Тик раз в секунду в `app.js` пересчитывает статусы от текущего времени; бип срабатывает на переходе `waiting → due` (по одному разу на позицию, отмечается в состоянии) и один раз в момент подачи.

## Архитектура файлов

```
index.html      — разметка, подключение модулей
style.css       — стили: светлая «бумажная» тема в духе vibecoded.ru
schedule.js     — чистая логика (единственный модуль с тестами)
app.js          — DOM, тик, Web Audio, localStorage, Wake Lock, регистрация SW
sw.js           — cache-first офлайн, версия кэша строкой
manifest.json   — PWA-манифест (standalone, русское имя)
icon.svg        — иконка (плита/конфорка), одна, SVG
test/schedule.test.mjs — node --test
```

## Звук и «не гаснущий экран»

- **Web Audio**: тройной бип осциллятором (без аудиофайлов). AudioContext создаётся по первому пользовательскому клику (политика автовоспроизведения). Кнопка-тумблер «звук вкл/выкл» рядом с отсчётом, состояние в localStorage.
- **Wake Lock API**: пока таймлайн активен, держим `screen` wake lock (телефон лежит на кухне с открытым планом — экран не гаснет, тики и бипы живут). Повторный захват на `visibilitychange`. Если API недоступен — молча работаем без него.
- Фоновые вкладки не гарантируют таймеры — это осознанное ограничение MVP, Wake Lock его закрывает для основного сценария. Push/Notification API не используем (трение с разрешениями).

## Офлайн и установка

- `sw.js`: cache-first для всех статических файлов, имя кэша `kitchen-vN` — смена N инвалидирует кэш при деплое.
- `manifest.json`: `name: «Кухонный оркестратор»`, `short_name: «Кухня»`, `display: standalone`, `theme_color`/`background_color` из палитры, иконка SVG (+ maskable).
- Деплой: GitHub Pages из корня `main`. Всё по относительным путям (работает и под `/kitchen-orchestrator/`).

## Хранение

`localStorage["kitchen-plan"]`: `{ serveTime: "HH:MM", items: [{id, name, minutes}], sound: bool, notified: {id: bool} }` — сохраняется на каждое изменение, восстанавливается при загрузке. `notified` не даёт бипать повторно после перезагрузки страницы в середине готовки.

## Крайние случаи

- Пустой список / нет времени — таймлайн скрыт, подсказка «добавь блюда и время подачи».
- `minutes ≤ 0` или пустое название — строка не участвует в расчёте, помечена как невалидная.
- Старт в прошлом — статус `due` немедленно, пометка «ставь сейчас», один бип.
- Переход через полночь — работает через `resolveServeDate` (завтра).
- Смена времени/состава во время готовки — полный пересчёт, `notified` сбрасывается для позиций, чей старт снова в будущем.

## Тесты (`node --test`, без браузера)

- сортировка по старту; стабильность при равных стартах;
- статусы во все четыре фазы (границы: ровно start, start+60с, ровно serveAt);
- `resolveServeDate`: сегодня / завтра / ровно сейчас;
- старт в прошлом → `due` сразу;
- невалидные позиции отфильтрованы.

UI-слой проверяется вручную в браузере (Claude in Chrome): ввод плана, таймлайн, статусы, установка PWA.

## Вне рамок MVP

- Библиотека рецептов, шаблоны планов, шаринг ссылкой.
- Модель зависимостей этапов («после духовки — отдых»): строки-этапы вводятся руками.
- Push-уведомления, вибрация.
- Тёмная тема (светлая «бумажная», как у витрины).
- Метрика/телеметрия — отдельное решение, не здесь.
